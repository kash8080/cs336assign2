Nested Checkpointing

Backprop through a block needs the intermediate values that block produced on the way forward. You can keep them, which costs memory, or throw them away and rebuild them when backward needs them, which costs compute. Nesting checkpoints lets you push that trade all the way: only one block's worth of intermediates ever exists at once.

The two facts you need

What a block keeps, and what a checkpoint changes

1. Backward through block i needs its residuals Rᵢ

hᵢ is the activation passed between blocks (batch × seq × d_model). Rᵢ is everything block i saved for backward: attention probabilities, the MLP hidden layer, norm statistics. It is many times bigger than hᵢ. On this page one h = 1 unit and one R = 8 units (illustrative).

Without checkpointing, the forward pass keeps every Rᵢ alive until backward reaches block i. That is N of them at the peak.

2. A checkpoint keeps only its input

The nesting rule. While a checkpoint reruns its region, any checkpoint inside that region acts like a checkpoint again: it keeps only its own input and drops its insides. That is what makes nesting useful. It lets you choose, at every level of the rerun, how much gets kept.

Every layer keeps its residuals until backward reaches it.

from torch.utils.checkpoint import checkpoint

def chain(blocks, x, tp):
    def run(k, h):          # applies blocks[0..k-1]
        if k == 1:
            return blocks[0](h, tp)
        h = checkpoint(run, k - 1, h, use_reentrant=False)
        return blocks[k - 1](h, tp)
    return checkpoint(run, len(blocks), x, use_reentrant=False)

output = chain(self.layers, output, tp)

Nested chain: O(1) memory, O(N²) compute.

def tree(blocks, x, tp):
    if len(blocks) == 1:
        return blocks[0](x, tp)
    mid = len(blocks) // 2
    x = checkpoint(tree, blocks[:mid], x, tp, use_reentrant=False)
    return checkpoint(tree, blocks[mid:], x, tp, use_reentrant=False)

output = tree(self.layers, output, tp)

Halving tree: O(log N) memory, O(N log N) compute. A good practical middle ground.

What chain expands to for N = 4

C4( C3( C2( C1( x₀ → B0 ) → B1 ) → B2 ) → B3 )

Every checkpoint Cₖ starts at the same tensor, x₀, so each one's "saved input" is just another reference to it. Nothing new gets stored. When backward reaches B3, C4 reruns B0–B3 from x₀. B0–B2 run inside C3, so they keep nothing, and only B3 keeps R₃. Then C3 reruns B0–B2 so that only B2 keeps R₂, and so on down the chain. B0 gets rerun N times, which is where the N²/2 compute comes from.

Written answer

Part (a) in five sentences

Nest the checkpoints as a left-leaning chain, Ck = checkpoint(Bk−1 ∘ Ck−1), with the outermost CN wrapping the whole stack. Every checkpoint in the chain saves the same tensor, the stack input x₀. As a result the forward pass keeps no per-block residuals at all.

During backward, reaching block k reruns blocks 0…k−1 from x₀. Blocks 0…k−2 run inside the inner checkpoint and keep nothing. Only block k−1 rebuilds its residuals, which are freed right after its backward step.

At any moment only one block's residuals (plus x₀ and the gradient in flight) are alive. Peak activation memory is O(1) in N, the minimum possible, because backprop through a block needs that block's residuals. Compute is O(N²): N + N(N+1)/2 block forwards. Flat checkpointing cannot get below O(√N), and the halving tree trades this down to O(log N) memory for O(N log N) compute.

Practical caveat: the chain nests N checkpoints deep. Use use_reentrant=False. The reentrant version keeps each level's recomputed output alive during backward, which brings back O(N) boundary tensors (the "bookkeeping" the problem says to ignore).
